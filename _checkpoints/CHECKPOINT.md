## 로컬 개발

```bash
cd ~/ssentif-redesign && python3 dev-server.py   # → http://127.0.0.1:8990
```

- ⚠️ **`python3 -m http.server` 쓰지 말 것** — Cache-Control을 안 보내서 파일을 고쳐도
  브라우저가 옛 HTML을 캐시에서 꺼내 쓴다(탭 전환 시 옛 화면 증상). `dev-server.py`가
  no-store 헤더를 붙인 대체 서버다. 라이브(Vercel)는 vercel.json must-revalidate로 문제없음.
- style.css는 `?v=N` 캐시버스팅 (**현재 v=2**). 수정 시 HTML들의 `?v=` 번호를 함께 올릴 것.
- **배치 커밋 원칙**: 사용자가 "배포해줘"라고 할 때만 commit+push.
- **카피 작업 원칙**: 반드시 제안 먼저, 승인 후 구현. 제안 2회 연속 거절 시 변주를 멈추고
  "어떤 걱정을 해소해야 하나"를 물을 것.

## 2. product.html (2026-07-22 전면 재구성, 배포됨)

### 구조 — 2묶음 카드 교차 (라포매니저 레퍼런스)

```
히어로  "수업하는 사람과 운동하는 사람, 그리고 운영하는 사람까지"
        + 점프 버튼 2개(#part-a / #part-b)
Part 1 · 강사와 회원 (라이트) — 대분류 6개 · 카드 18장
        스케줄5 / 수업일지3 / 루틴 처방3 / 식단2 / 성장 데이터3 / 소통2
Part 2 · 관리자 (다크 #0D0F12) — 대분류 4개 · 카드 12장
        운영 대시보드4 / 회원 관리3 / 정산과 팀3 / AI 어시스턴트2
CTA 밴드 (4페이지 공통, 변경 금지)
```

### 핵심 결정과 이유
- **관리자를 뒤에 배치** (사용자와 논의 후 확정, 한 번 앞으로 바꿨다가 되돌림):
  ① 기록→데이터 인과 서사가 한 방향("쌓이면 모입니다"는 뒤에 있어야 성립)
  ② 원장의 구매 장벽은 "강사·회원이 쓸까"라 그 해소가 먼저
  ③ 구매자 가치가 CTA 직전에 오도록. 관리자 바로가기는 히어로 점프 버튼이 해결.
- **라포식 경험 분해**: 같은 기능도 역할별 카드로 쪼개 `기능 라벨 + 가치 헤드라인` 2단 제목.
- **역할 태그**: 강사(민트틴트)/회원(블루틴트)/함께/관리자(다크용 민트).
- **목업 30개**: 실제 앱 UI 문자열·수치 구조 기반 HTML/CSS. 회원=폰 / 강사=태블릿 /
  관리자=데스크톱(점 3개 창) 프레임. **민트색은 AI 요소 전용**(앱 디자인 규칙).
- **수치는 전부 가안**(사용자 지시). 미구현 기능 명시도 허용.
- 추후 목업만 실제 이미지로 재작업 예정.

### 재생성 스크립트 (중요)
`_checkpoints/build_product.py` — **product.html 전체를 이 스크립트가 생성했다.**
카드 추가·순서 변경·목업 수정 같은 구조 작업은 HTML을 직접 고치는 것보다 이 스크립트를
수정해 재실행하는 편이 안전하다(순서 실험 때 이 방식으로 즉시 원복한 전례).
```bash
python3 _checkpoints/build_product.py   # → product-new.html 생성(현 product.html에서 nav/footer 추출)
# 검토 후 메타 이식·교체는 세션 히스토리 참고
```

### 이번 세션 확정 사항
- **히어로 구조 스트립**: 기기 중심 SVG 아이콘(폰/태블릿/모니터) 카드 3장 —
  강사(태블릿·모바일) / 관리자(PC·태블릿) | 회원(모바일). "코치앱/회원 앱" 라벨 텍스트는
  삭제됨(사용자 지시). **3페이지 바이트 단위 동일**해야 함(MD5 대조).
- **공통은 단일 블록**: `sec-common` 하나(8개 아티클)가 강사·관리자 두 페이지 본문 맨 앞에
  동일하게 들어감. 목차도 `공통` 그룹 하나. 별도 탭·분산 배치 모두 폐기된 안.
- **목차 라벨은 `.toc-group-label`만 사용** — `.toc-cat`은 CSS 정의가 없던 버그 클래스(제거됨).
- 워딩 톤 §1 적용 완료(구어체 0건).

### 검증 3종 세트 (가이드 수정 후 반드시)
① 목차 앵커 = 본문 id 순서 일치 ② 죽은 CSS + 정의 없는 클래스(양방향)
③ 공통 섹션·구조 스트립 MD5가 페이지 간 동일
