> ⚠️ 홈페이지는 "AI 매니저가 함께하는"을 전면에 내세우는데 **앱의 AI는 아직 동작하지 않는다.** 문구 조정 여부는 사용자 판단 필요.

**작업 방침**: 캡처 → 개인정보 마스킹(회원명 `김O지` 식, 전화 뒷자리 `****`) → `assets/app/`에 저장 → index.html에 `<img>` 삽입.

**모드 소개에서 확립된 삽입 패턴**(나머지 섹션도 동일하게):
- 기기 프레임 CSS는 **살리고 내부 CSS 목업만** `<img>` 로 교체.
- 프레임 안쪽 요소에 **고정 height 대신 `aspect-ratio`** 를 준다(예: `.ms-browser-body { aspect-ratio: 676/425 }`). 고정 height를 쓰면 컬럼 폭이 예상과 달라 `object-fit:cover` 가 이미지 좌우를 잘라먹는다(실제로 관리자 대시보드 우측 컬럼이 잘렸다).
- `<img>` 는 `width/height` 명시 + `loading="lazy" decoding="async"`.
- 마크업을 지우면 **죽은 CSS가 남는다** — `grep -c 'class="[^"]*\b<클래스>\b'` 로 0 확인 후 규칙 삭제(모드 소개에서 16개 제거).

**합성 패턴(6 STEP에서 확립)** — `compose.py`:
- 카드가 세로로 길어서 앱의 가로로 넓은 패널을 그대로 넣으면 납작해진다. **부분 크롭 2개를 `stack()`으로 세로로 쌓아** 카드 비율에 맞춘다. 예: 급여정산 = 요약바 + 직원카드 / 운영진단 = 운영위험도 + 매출현황.
- 좌표는 **computer-use 스크린샷(1372×882) 기준**으로 적고 `R()`이 창 원점(152,117)·배율 2.494로 변환한다. **창 위치·크기가 바뀌면 이 상수를 다시 재야 한다.**
- `piece(..., radius=18)`로 모서리를 둥글리면 앱 카드처럼 보인다.

⚠️ **마스킹 반복 함정(이번에 네 번 겪음)**: 덮개 사각형이 원본 글자보다 **작으면 위/왼쪽에 잔상**이 남는다. 눈대중 금지 — **어두운 픽셀의 행/열을 스캔해 실측**한 뒤 상하좌우 2~3px 여유를 준다. 폰트 크기도 원본 글자 높이에서 역산할 것(글자높이 ≈ size × 0.75).

⚠️ **개인정보 — 쓰면 안 되는 화면**: 회원 **신체변화 탭의 체형 사진**은 실제 인물 전신 사진이다. 마스킹으로 해결되지 않으니 **체성분 카드·차트 영역만** 잘라 쓸 것.

⚠️ **미리보기 스크린샷 함정**: 이 페이지는 스크롤 하이재킹이 있어 `window.scrollTo`/`scrollIntoView` 가 되돌려진다. 섹션을 보려면 **형제 요소를 `display:none` 으로 숨겨 격리**한 뒤 찍을 것. `fade-up` 은 `opacity:1; transform:none` 으로 강제.

  → pg_net(net.http_post) → 슬랙 직접 POST

- **Flutter SDK 미설치** — 앱 소스는 grep으로 문자열 확인만. 앱 기능·문구는 반드시 소스로 검증(추측 금지 — 매칭/루틴 보관함 오류 전례)
- **앱 소스는 git 아님** — 수정 금지(개발자 담당), 롤백 불가
- 작업 폴더 밖 대량 수정은 자동 승인 정책에 차단됨 — 우회 말고 사용자에게 알릴 것
- Supabase SQL Editor는 **결과 셀이 길면 잘려서 표시**된다. 긴 함수 본문을 읽으려 하지 말고 통째로 재작성이 빠르다.
- SQL 자리표시자(`PASTE_URL_HERE`)를 치환하지 않고 실행하면 그 문자열이 그대로 들어간다.
- Python에서 CSS 문자열을 `%` 포맷으로 다루면 `%` 값과 충돌 — `.replace()` 사용
